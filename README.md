# JSCC — Job Search Command Center

[![ci](https://github.com/jgray314/jscc/actions/workflows/ci.yml/badge.svg)](https://github.com/jgray314/jscc/actions/workflows/ci.yml)

A tracker for a real job search. It reads job postings, scores them against a profile, flags stale applications, and drafts routine follow-ups. Anything non-routine goes to a person as a briefing card instead of a draft, and nothing is ever sent automatically. Every model step is tested against recorded real model output, and the numbers are reported with their limits.

Part of the [ai-portfolio](https://github.com/jgray314/ai-portfolio) index. Built to v1 in six phases with an AI coding agent; [CHANGELOG.md](CHANGELOG.md) has the step-by-step arc. Two companion docs go deeper: [docs/how-i-built-this.md](docs/how-i-built-this.md) (the narrative) and [docs/technical-reference.md](docs/technical-reference.md) (architecture, repo layout, commands, phase status).

## What's worth reading

If you have ten minutes, start here.

1. **Eval results, with every round on the record.** Each model step ships behind an eval suite whose pass bar lives in code. The failed rounds are published next to the passing ones. → [evals/README.md](evals/README.md), [`jscc/evals.py`](jscc/evals.py)
2. **Safety by construction, not discipline.** One definition of personal data, enforced at both exits: git and every model call. There is a single call path to the model, so no caller can skip redaction. → [`jscc/personal_data.py`](jscc/personal_data.py), [`jscc/sanitizer.py`](jscc/sanitizer.py), [`jscc/stage_call.py`](jscc/stage_call.py), [ADR-005](decisions/005-sanitizer-authenticity.md), and the one-page [threat model](docs/threat-model.md): thirteen threats, each with its control and an honest status.
3. **Knowing when not to automate.** The drafter first decides whether a case is routine. Anything that isn't, or that needs a fact nobody recorded, goes to a person. Drafting something that needed a human is a zero-tolerance failure in the eval. → [D10](docs/design-principles.md#d10--drafter-routing-first-routine-only-composition)
4. **Reviews that overturned earlier calls.** A later review found a DNS-rebinding hole in the URL fetcher that an earlier review had rated low-risk. It was fixed in code, not with a note. → [`jscc/fetcher.py`](jscc/fetcher.py) (`_pinned_resolution`), and [docs/gate-reviews.md](docs/gate-reviews.md) for six worked findings and where the review process falls short.
5. **Decisions with the rejected options written down.** Seven ADRs and ten design principles, including what was dropped: RAG in the drafter, a hosted demo, a multi-agent orchestrator. → [decisions/](decisions/), [docs/design-principles.md](docs/design-principles.md)

One number I got wrong, corrected in the open: I believed review and hardening work was "the other 80%" of the effort. Commit timestamps put it at about half (48/52). → [docs/lessons-learned.md](docs/lessons-learned.md), [`scripts/active_time.py`](scripts/active_time.py)

## Eval results

No `ANTHROPIC_API_KEY` is configured for this project. Every result below comes from real model output captured by hand through Claude.ai chat, one fresh chat per case, then replayed through the harness.

| Suite | Result | Bar |
|---|---|---|
| Extraction | 33/38 (87%) | 80% |
| Fit scoring | 29/30 (97%) | 80% |
| Routing | 38/39 (97%) | 85%, and zero false-routine |
| Composition | 25/28 (89%) | 75%, and every must-ask case asks |

None of these is a held-out rate. Each prompt was revised after seeing its own cases. Extraction, for example, is 32/36 on the cases it was tuned on and 1/2 on two held-out injection cases added later. Routing's 10 held-out cases went 10/10: a first look, not a rate. Every round, miss, and limit is in [evals/README.md](evals/README.md).

## Quick start

```bash
uv sync
uv run python -m jscc validate-config
uv run python -m jscc db init
uv run python -m jscc seed --random-seed 42 --now 2026-08-28T12:00:00+00:00
uv run python -m jscc report --now 2026-08-28T12:00:00+00:00
```

Default mode is `synthetic`. Switch by env: `JSCC_DATA=real`. Neither DB is tracked — the synthetic one is regenerated by the `seed` command above, deterministically, which is why the sample output below reproduces.

## Running the dashboard

The dashboard (`jscc/web/`, ADR-007) is the same read/write logic as the CLI, rendered over HTTP. Same mode rules as everything else: the `JSCC_DATA` env var picks synthetic vs. real, and the SYNTHETIC MODE banner in the page header tells you which one you're looking at.

```bash
uv sync
uv run jscc db init
uv run jscc seed --random-seed 42
uv run jscc serve --port 8000
```

Then open http://127.0.0.1:8000. No `ANTHROPIC_API_KEY` is required for browsing. Running it against real data, the bind-address and request-guard details, and what the DLQ resolve form does without a key are in [docs/technical-reference.md](docs/technical-reference.md#running-the-dashboard-in-production).

## Sample drafter output

`followup` prints one of two things. These were produced by replaying recorded real-model responses (Haiku for routing, Sonnet 5 for composition) for two eval fixtures through the same renderers the command uses. Offline, against the stub clients, `followup` on the seeded database always prints a briefing card, because the stub router answers non-routine.

A routine situation (the history records a full-loop onsite) gets a draft:

```
Subject: Thank you for the onsite

Thank you all for the time on Thursday. I really enjoyed the full loop, from the system design session to the two behavioral rounds and the panel with the skip-level.

The conversations left me even more interested in the Engineering Manager, Platform role. It was great to get a real sense of how the team thinks about the work, and I appreciate everyone's openness throughout the day.

Please pass along my thanks to the whole panel. Happy to answer any follow-up questions as you move ahead.

Best,
```

A non-routine one (the candidate has decided to withdraw) gets a card and no draft:

```
HANDLE MANUALLY -- Cedar Ridge Analytics: Engineering Manager
Stage: closed
Why: Declining an application affects the relationship with the recruiter and company, and how the candidate communicates this decision shapes whether that door stays open for future opportunities.
Weigh before replying:
  - Tone and wording should feel gracious and respectful, not dismissive of the role or company
  - How to frame the scope mismatch reason without sounding like the candidate is backing away or hesitating
  - Whether to signal openness to future opportunities or roles at the company
  - How much detail to include about why the role no longer fits, given the candidate's other conversations have progressed further
Application: app-26
```

## Architecture and decisions

Every model step reaches the model through one path (`stage_call.py`), so no caller can skip the sanitizer or the cost meter ([D7](docs/design-principles.md#d7--dual-use-data-safety-structural-not-disciplinary)). Storage is a mode-stamped SQLite layer shared by the CLI and the dashboard, so the two can't disagree on what's stale. Full diagram and module detail: [docs/technical-reference.md](docs/technical-reference.md#architecture).
